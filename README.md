# cc-watermark-lab

CC_Codex 二期（26.11）**数据工程**产品线：**血缘水印台**（BlackSheep + Alpine CDN + SQLite）。

## 一句话骨架（自有，非外仓抄题）

**产出表水印模板 → 批次盖印 → 下游追索 → 缺口对账**

与现有七线正交（不是采集目录、ETL 管道、同步源、解析入库、编排流、种子摄取、留存裁撤）。
不碰外仓常见指纹（Feed 归并 / CDC 游标 / 质检签发 / Slicegate 类仓名）。

## 领域

- **所属领域**：数据工程
- **子方向**：数据血缘与水印（产出表盖印 / 追索闭环）

## 技术栈

| 层 | 选型 |
|----|------|
| 后端 | Python 3.12、BlackSheep、Uvicorn、SQLite |
| 前端 | 原生 JS SPA（全中文，底栏），雾灰底 + 青柠强调；不依赖外网 CDN |
| 测试 | pytest + httpx（本地秒级闭环，优先于 compose） |

## 基线已通主链

1. 产出表水印模板（表名 / 列名 / 现行版本）
2. 向运行批次盖印水印值
3. 按水印值追索下游批次
4. 缺口对账（已盖印 vs 应盖印）

## 追索深度限制（本期切口已做）

追索不设深度时，深链会把无关下游也拖进缺口，对账随之膨胀。本期加了深度
限制，并在两条可行凭证里选定 **第二条**：

- **凭证路线：旁路版本表 + 事务内判定**（另一个方案是把深度配置落成不可变
  文件哈希并把旧配置推进只读历史；本仓未选）。深度唯一来源是
  `trace_depth_policies` 表：追加式写入，`UPDATE`/`DELETE` 被触发器拒绝，
  旧版只读留证。
- **绑码**：`DP-v{版号}-{内容哈希前 12 位}`。内容哈希覆盖版号与深度上限，
  页面顶栏、深度卡片、追索裁定、缺口复验共用同一绑码。
- **事务内一次裁定**：追索在单个 `BEGIN IMMEDIATE` 事务里读当前版本 → 算多跳
  深度 → 写证据 → 再对外回结果。改深度也必须在该写锁下追加新版本，因此
  “并发一边改深度一边追索”不会双写同版或同一条边。
- **失败只回短句**：超深下游一律 409，短句 `追索被拒：存在超深下游，已按深度上限拦截`，
  同时回绑码/版号/上限/被拦批次；拒绝为终态，不放行任何节点。
- **吃旧深度即停**：页面提交追索时带上亮出的绑码；与库内当前绑码不一致直接停。
  版本行自身哈希/绑码不自洽也停，四处页面一起停。
- **四处同查**：深度卡片、追索详情、批次列表、缺口台统一走 `/api/console`
  的单事务快照，不会出现卡片亮 v2、列表按 v1 标注的错位。
- **库内留证**：`trace_runs`（每次裁定）、`trace_edges`（走过的边）、
  `gap_verifications`（复验）、`gap_reports`（对账绑码/上限/排除数）。
- **缺口复验**：应盖印口径排除超深下游；复验按当前深度重跑，超深下游仍被拒
  才算通过；若换版后反而会放行，记 `不一致`。

审计接口：`GET /api/trace-audit` 核验每条追索证据的绑码/上限/裁定是否对齐。

预留切口（未做，供后续功能题）：模板换版生效窗、盖印作废回灌、批量盖印互斥、跨表依赖冻结等。
